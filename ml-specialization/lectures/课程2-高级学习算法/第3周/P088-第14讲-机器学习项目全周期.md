> *Full cycle of a machine learning project*（9:25）

**〔00:02〕** 到目前为止，我们讨论了很多关于如何训练模型的内容。

**〔00:07〕** 也稍微谈了一下如何为你的机器学习应用获取数据。

**〔00:12〕** 但是当我构建一个机器学习系统时，我发现训练模型只是整个拼图的一部分。

**〔00:20〕** 在这个视频中，我想与你分享我所认为的一个机器学习项目的完整周期。

**〔00:27〕** 也就是说，当你在构建一个有价值的机器学习系统时，需要思考和规划哪些步骤。

**〔00:36〕** 我们来看看，让我用语音识别作为例子来说明一个机器学习项目的完整周期。

**〔00:45〕** 机器学习项目的第一步是确定项目范围。

**〔00:49〕** 换句话说，决定项目是什么以及你想要做什么。

**〔00:54〕** 例如，我曾决定从事语音搜索的语音识别工作，也就是通过对着手机说话而非打字来进行网络搜索。

**〔01:04〕** 这就是项目范围界定，在决定了要做什么之后，你必须收集数据。

**〔01:12〕** 要决定你需要哪些数据来训练你的机器学习系统。

**〔01:18〕** 然后，着手获取音频以及你数据级的转录文本或标签。

**〔01:24〕** 这就是数据收集。

**〔01:27〕** 在你有了初步的数据收集之后，就可以开始训练模型了。

**〔01:33〕** 那么在这里，你将训练一个语音识别系统，并进行误差分析，然后迭代的改进你的模型。

**〔01:42〕** 很常见的是，在你开始训练模型之后，误差分析或偏差方差分析会告诉你，你可能需要回过头去收集更多的数据。

**〔01:52〕** 也许是收集更多方方面面的数据，或者只是收集你的误差分析显示，需要改进学习算法性能的特定类型的数据。

**〔02:06〕** 例如，有一次在处理语音问题时，我意识到当背景中有汽车噪音时，我的模型表现尤其糟糕。

**〔02:15〕** 如果听起来像是有人在车里说话，我的语音系统就表现不佳，于是我决定获取更多数据。

**〔02:23〕** 实际上是使用数据增强技术来获取更多听起来像是在车里的语音数据，以提高我学习算法的性能。

**〔02:32〕** 就这样，你在这个循环中迭代几次，训练模型进行误差分析，再回过头去收集更多数据。

**〔02:40〕** 也许这样做上一段时间，直到最终你认为模型足够好，可以部署到生产环境中了。

**〔02:49〕** 这意味着你让用户可以实际使用它。

**〔02:53〕** 而当你部署一个系统时，你还必须确保继续监控系统的性能并维护系统。

**〔03:01〕** 以防性能变差时，能将其性能恢复。

**〔03:05〕** 除了只是把你的机器学习模型托管在服务器上，关于为什么需要维护这些机器学习系统，我将在下一张幻灯片中再多讲一点。

**〔03:16〕** 但在这次部署之后，有时你会意识到它的表现不如你预期的那样好。

**〔03:23〕** 你就会回去再次训练模型以改进它，甚至可能回过头去获取更多数据。

**〔03:30〕** 事实上，如果用户允许，并且你获得了使用生产部署数据的许可，有时来自你正在运行的语音系统的数据，能让你获得甚至更多的数据，用以持续改进你系统的性能。

**〔03:46〕** 我想，你已经理解了确定项目范围意味着什么，并且我们在这门课中已经讨论了很多关于收集数据和训练模型的内容。

**〔03:57〕** 但让我再和你分享一些关于在生产环境中部署可能是什么样的更多细节。

**〔04:04〕** 在你训练出一个高性能的机器学习模型后，比如说一个语音识别模型，一种常见的部署模型的方法是拿出你的机器学习模型，并将其部署在一个服务器上。

**〔04:20〕** 我将这个服务器称为推理服务器，它的任务就是调用你那训练好的机器学习模型来进行预测。

**〔04:28〕** 然后，如果你的团队实现了一个移动应用，比如一个搜索应用，那么当用户对着移动应用说话时，该移动应用就可以发起一个 API 调用。

**〔04:44〕** 将录制好的音频片段传递给推理服务器。

**〔04:48〕** 推理服务器的任务是对其应用机器学习模型，然后将模型的预测结果返回给它。

**〔04:56〕** 在这个例子中，这个预测结果就是所说内容的文本转路。

**〔05:02〕** 这将是一种常见的实现应用的方式，该应用通过 API 调用一个推理服务器。

**〔05:09〕** 该服务器让你的模型基于输入 X 反复做出预测。

**〔05:15〕** 这将是一个常见的模式，即根据所实现的应用，你发起一个 API 调用给你的学习算法输入 X，然后你的机器学习模型将输出预测结果，比如 Y hat。

**〔05:31〕** 为了实现这一点，可能需要一些软件工程来编写完成所有这些事情的代码。

**〔05:40〕** 而且，根据你的应用是需要服务辽辽少数用户，还是数百万用户。

**〔05:46〕** 所需的软件工程量可能大相竞停。

**〔05:50〕** 我曾在我笔记本电脑上构建过只服务少数用户的软件。

**〔05:55〕** 我也构建过服务数亿用户，需要大量数据中心资源的软件。

**〔06:01〕** 根据所需的应用规模，可能需要进行软件工程以确保你的推理服务器能够做出可靠且高效的预测。

**〔06:13〕** 同时，希望其计算成本不会太高。

**〔06:17〕** 可能需要进行软件工程来管理扩展以应对大量用户。

**〔06:22〕** 你通常需要记录你获得的数据，包括输入 X 以及预测结果 Y。

**〔06:28〕** 当然，前提是用户隐私和许可允许你存储这些数据。

**〔06:34〕** 而且这些数据如果你能获取，对于系统监控也非常有用。

**〔06:40〕** 例如，我曾经基于我有的某个数据级，构建了一个语音识别系统。

**〔06:46〕** 但是，当有新的名人突然变得众所周知，或者选举导致新的政治家当选时，人们会搜索这些没有在训练集中出现过的新名字。

**〔06:58〕** 我的系统对此表现很差。

**〔07:01〕** 正是因为我们监控了系统，才使我们能够发现数据何时发生了偏移。

**〔07:08〕** 算法何时变得不那么准确。

**〔07:11〕** 这使我们能够重新训练模型，然后进行模型更新。

**〔07:17〕** 用新模型替换旧模型，部署过程可能需要一定量的软件工程。

**〔07:25〕** 对于某些应用，如果你只是在笔记本电脑或一两台服务器上运行它，也许不需要太多的软件工程。

**〔07:37〕** 但对于其他情况，并且根据你所在的团队，有可能你负责构建机器学习模型。

**〔07:45〕** 但可能有一个不同的团队负责部署它。

**〔07:49〕** 但是机器学习领域有一个正在发展的方向，叫做 MLOPS。

**〔07:56〕** 它代表机器学习运维。

**〔07:59〕** 这指的是，如何系统性的构建部署和维护机器学习系统，以完成所有这些事情，确保你的机器学习模型可靠。

**〔08:10〕** 可扩展有良好的日制纪录，受到监控。

**〔08:19〕** 并且你有机会事实地对模型进行更新，以保持其良好运行的实践。

**〔08:27〕** 例如，如果你要将系统部署给数百万人，你可能希望确保你有一个高度优化的实现，这样为数百万用户服务的计算成本就不会太昂贵。

**〔08:40〕** 在这门课和上一门课中，我们花了大量时间讨论如何训练机器学习模型。

**〔08:48〕** 而这，绝对是确保你拥有一个高性能系统的关键部分。

**〔08:54〕** 如果你需要将系统部署给数百万人，那么这些很可能是你在那时候也必须考虑和解决的一些额外步骤。
